    GWeather-4.0

    GJS TypeScript type definitions for GWeather-4.0 using ts-for-gir v4.6.0.

    This package contains type declarations only. It ships no runtime code, so it adds nothing to your program and works with any bundler or none at all.

    Install

    npm install @girs/gweather-4.0

    Any package manager works. The package has no dependencies beyond other @girs/* type packages.

    What it exports

    Import What you get
    @girs/gweather-4.0 the namespace as a default export, plus the ambient and global declarations
    @girs/gweather-4.0/ambient only the gi:// module declarations
    @girs/gweather-4.0/import only the imports.gi declarations
    @girs/gweather-4.0/gweather-4.0 the namespace, without the side-effecting declarations

    Three ways to import

    Which one you use depends on how you write imports elsewhere, not on your toolchain.

    As a module

    import GWeather from '@girs/gweather-4.0';

    As gi://

    GJS resolves gi:// at runtime. To give it types, reference the package once, either from your entry point or from tsconfig.json:

    import '@girs/gweather-4.0';

    { "include": ["@girs/gweather-4.0"] }

    Then the runtime spelling type-checks:

    import GWeather from 'gi://GWeather?version=4.0';

    Referencing @girs/gweather-4.0/ambient instead pulls in these declarations alone. See ambient modules.

    As imports.gi

    GJS's global object works the same way, via @girs/gweather-4.0/import:

    const GWeather = imports.gi.GWeather;

    Building

    The declarations need no build step. If you bundle, every bundler works, since there is no runtime code to resolve. The examples show working setups for several.
